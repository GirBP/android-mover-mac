# SPEC — Android Mover (переміщення файлів Android → Mac)

> Визначення «готово»: короткий і перевірний перелік критеріїв прийому.

## Problem
На macOS немає нормального способу перенести файли з Android-телефона так, як на Windows через Провідник: відкрив, вибрав теку, перемістив. Android File Transfer застарілий і глючний (MTP-стек на macOS ненадійний). Потрібен простий нативний додаток: підключив телефон → вибрав теку на телефоні → вибрав теку на Mac → перемістив, **зі збереженням дат файлів** (дата модифікації + дата створення у Finder) і всіх внутрішніх метаданих (EXIF тощо — вони всередині файлів і не втрачаються при побайтовому копіюванні).

## Target user
Власник MacBook (Apple Silicon, macOS 14+) з Android-телефоном. Українськомовний інтерфейс. Один раз вмикає «Налагодження USB» на телефоні (як компенсацію за відсутність MTP у macOS), далі — все в один клік.

## Must-have capabilities (the few that matter)
1. Додаток виявляє підключений телефон через ADB; для станів «ADB не встановлено» (кнопка встановлення), «телефон не знайдено» (інструкція, як увімкнути USB-налагодження) і «не авторизовано» (підказка підтвердити на екрані телефона) показує зрозумілий онбординг.
2. Показує теки телефона (назва, розмір, дата; сортування; швидкі закладки DCIM/Download/Pictures; кирилиця і пробіли в іменах).
3. Копіює або переміщує вибрані файли/теки на Mac, показуючи прогрес; скасувати можна в будь-який момент. Переміщення спершу копіює, тоді **перевіряє копію (кількість і розміри файлів)** і лише після цього видаляє файли з телефона.
4. Збереження дат: mtime з телефона (через `adb pull -a`) + виставлення creationDate = mtime на APFS, щоб Finder показував правильні дати.

## Non-goals (explicitly out of scope for now)
- MTP-режим без USB-налагодження.
- Підпис/нотаризація додатка, App Store.
- Хмара/акаунти/remote access; screen mirroring; SMS/дзвінки.

## Acceptance criteria (each must be objectively checkable)
- [x] `swift build` і `swift test` зелені (движок покритий тестами на mock-adb).
- [x] Тест: скопійований через движок файл має mtime секунда-в-секунду як у джерела і creationDate == mtime.
- [x] Тест: «переміщення» видаляє джерело лише після успішної верифікації; при зіпсованому копіюванні джерело НЕ видаляється і повертається помилка.
- [x] Тест: імена з кирилицею, пробілами й апострофами проходять шлях список→pull→верифікація→видалення без спотворень.
- [x] Тест: колізія імен у теці призначення вирішується автоперейменуванням «name (1)».
- [x] `scripts/build_app.sh` збирає `dist/Android Mover.app`; запущений бінарник живе ≥2 с (smoke).
- [ ] Без adb додаток показує онбординг зі станом «встановити ADB» (UI-шар без автотесту — сценарні тести через AppModel).
- [x] Тест: push Mac→Android іде через тимчасову теку на телефоні й верифікується (кількість+розміри) до появи у видимому місці; битий push не лишає часткових файлів у призначенні.
- [x] Тест: колізія імен на телефоні при push вирішується автоперейменуванням; push у небезпечний шлях (поза /sdcard|/storage) відхиляється.
- [x] Тест: обірваний pull докачує лише відсутні/биті файли і завершується успішною верифікацією; після вичерпання спроб — чесний провал без видалення джерела.

## Constraints
- Stack: Swift 6 (мова v5-режим) + SwiftUI, SPM executable → .app bundle; без зовнішніх залежностей.
- Транспорт: ADB (`pull -a`). Пошук adb: `$ADB_PATH` → Application Support → Homebrew/SDK-шляхи; вбудоване завантаження platform-tools з офіційного dl.google.com за кліком користувача.
- Видалення на телефоні — тільки під явно вибраними елементами; захист від видалення коренів (/sdcard, /storage/emulated/0).
- Чесність: жодних фейкових зелених; помилки транспорту показуються користувачу.

## Definition of done
Усі критерії прийому вище виконані; якщо прогрес заблокований рішенням, яке може ухвалити лише власник (наприклад, потрібен реальний телефон для фінальної перевірки), це фіксується в CHANGELOG.
