# QA на реальному пристрої

Чекліст ручної перевірки на живому Android-телефоні. На відміну від `scripts/e2e_device.sh`
(автоматичні golden-транскрипти і XCTest проти реального adb) це кроки, які людина проходить
очима: поведінка додатка, стан Галереї, повідомлення про помилки.

Кожна версія, що торкається транспорту (ADBClient/TransferEngine/PushEngine/mock_adb.py),
проходить цей чекліст на реальному телефоні перед тегом; результат записують у
`CHANGELOG.md` цієї версії рядком «QA-DEVICE пройдено (модель, дата)».

Колонки «Результат / Дата / Модель / Версія» заповнюються під час прогону; «Результат» —
✅ пройшло / ❌ провал (з описом) / ⏭ пропущено (з причиною, наприклад немає другого пристрою).

| Крок | Очікувано | Результат | Дата | Модель | Версія |
|---|---|---|---|---|---|
| Висмикнути кабель USB посеред **pull** великої теки (напр. `DCIM`) | Операція чесно провалюється (не зависає назавжди); прогрес/спінер зупиняється з повідомленням про помилку; джерело на телефоні лишається повністю неушкодженим; після повторного підключення кабелю додаток і adb працюють штатно без перезапуску | | | | |
| Висмикнути кабель USB посеред **push** (Mac → телефон) | У видимому місці на телефоні НЕ з'являється часткова копія (лишається щонайбільше тимчасова `.androidmover-tmp-*`, яку прибирає наступний прогін); Mac-джерело незмінне; після перепідключення штатна робота | | | | |
| Галерея (Google Фото / штатна Галерея) після **delete** фото/відео | Видалені медіафайли зникають із Галереї без ручного «Пересканувати» (best-effort MediaStore rescan після операції) | | | | |
| Галерея після **push** нового фото/відео в `DCIM` | Нові медіафайли з'являються в Галереї без ручного «Пересканувати» | | | | |
| Вільне місце на телефоні (`stat -f`, показується в UI біля назви пристрою) | Число збігається (з точністю до похибки блоку файлової системи) з «Налаштування → Про телефон → Сховище» на самому пристрої | | | | |
| Тека з ~5000 файлів (напр. `DCIM/Camera` за кілька років) | Лістинг завершується без таймауту (`ADBClient.findTimeout` = 180 с — перевірити, що укладається); прокрутка таблиці лишається плавною, немає зависання UI | | | | |
| USB-режим «Лише заряджання» (не MTP/передача файлів) | Додаток явно повідомляє, що не бачить файлову систему пристрою (а не мовчки показує порожній список чи невиразну помилку) | | | | |
| Mac уперше підключається до телефона (телефон питає «Дозволити налагодження USB?») | Діалог авторизації з'являється на екрані телефона; додаток коректно чекає, доки користувач підтвердить (стан `unauthorized`), а не падає й не зависає; після галочки «Завжди дозволяти» — штатна робота | | | | |
| Кілька Android-пристроїв підключено одночасно | Список пристроїв показує всі підключені серійники; перемикання між ними і операції на вибраному пристрої не плутають файли/шляхи іншого | | | | |
